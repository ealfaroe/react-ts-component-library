# Copilot Instructions for React TypeScript Component Library

## Project Context

This is a modern React component library built with TypeScript, designed for reusability and maintainability. The project uses cutting-edge tools and follows strict development patterns.

### Tech Stack & Architecture
- **React 19** with TypeScript 5.7 for type-safe component development
- **Vite 6** for fast development and optimized builds
- **Tailwind CSS 4** for utility-first styling with @tailwindcss/vite integration
- **Biome** for unified linting, formatting, and import organization (replaces ESLint + Prettier)
- **Vitest** with jsdom for component testing
- **Ladle** for component development and documentation (Storybook alternative)
- **React Testing Library** for user-centric testing approaches

### Project Structure Patterns
```
src/
├── components/           # Follow strict component structure
│   └── ComponentName/
│       ├── ComponentName.tsx        # Main implementation
│       ├── ComponentName.stories.tsx # Ladle stories
│       ├── ComponentName.test.tsx   # Vitest tests
│       └── index.tsx               # Clean exports
├── types/               # Centralized type definitions
│   └── ComponentName.types.ts
├── hooks/               # Custom React hooks
├── services/            # API and utility services
└── assets/             # Static resources
```

## Code Style & Standards

### TypeScript Requirements
- **Strict typing**: Never use `any`, prefer specific interfaces
- **Component props**: Always define interfaces in separate `.types.ts` files
- **Functional components**: Use `React.FunctionComponent<PropsInterface>` pattern
- **Export pattern**: Default export for components, named exports for utilities

### Component Development Pattern
```tsx
// Always follow this structure
import type { ComponentNameProps } from '../../types/ComponentName.types';

const ComponentName: React.FunctionComponent<ComponentNameProps> = ({
  prop1,
  prop2 = 'defaultValue',
  className,
  children,
  ...props
}) => {
  return (
    <div className={`base-classes ${className}`} {...props}>
      {children}
    </div>
  );
};

export default ComponentName;
```

### Type Definition Standards
```typescript
// ComponentName.types.ts
export interface ComponentNameProps {
  // Required props first
  requiredProp: string;
  
  // Optional props with clear descriptions
  optionalProp?: boolean;
  
  // Standard React props
  className?: string;
  children?: React.ReactNode;
  
  // Event handlers with proper typing
  onClick?: (event: React.MouseEvent<HTMLElement>) => void;
}
```

### Biome Configuration
- **Indentation**: Tabs (configured in biome.json)
- **Import organization**: Automatic sorting enabled
- **Recommended rules**: All enabled, never disable without good reason
- **Formatting**: Consistent across all files

## Testing Standards

### Vitest + React Testing Library Approach
```tsx
// ComponentName.test.tsx
import { render, screen, fireEvent } from '@testing-library/react';
import { describe, it, expect, vi } from 'vitest';
import ComponentName from './ComponentName';

describe('ComponentName', () => {
  it('renders with required props', () => {
    render(<ComponentName requiredProp="test" />);
    expect(screen.getByText('test')).toBeInTheDocument();
  });

  it('handles user interactions', () => {
    const mockHandler = vi.fn();
    render(<ComponentName requiredProp="test" onClick={mockHandler} />);
    
    fireEvent.click(screen.getByRole('button'));
    expect(mockHandler).toHaveBeenCalledTimes(1);
  });
});
```

### Testing Requirements
- **User-centric tests**: Test behavior, not implementation
- **Accessibility**: Include screen reader and keyboard navigation tests
- **Error states**: Test edge cases and error handling
- **Mock functions**: Use `vi.fn()` for event handlers and external dependencies

## Ladle Stories Pattern

### Story Structure
```tsx
// ComponentName.stories.tsx
import type { Story } from "@ladle/react";
import ComponentName from "./ComponentName";

// Default story showcasing basic functionality
export const Default: Story = () => (
  <ComponentName requiredProp="Default example" />
);

// Variant stories for different states
export const WithOptionalProps: Story = () => (
  <ComponentName 
    requiredProp="With options" 
    optionalProp={true}
    className="custom-styling"
  />
);

// Interactive story for event handling
export const Interactive: Story = () => (
  <ComponentName 
    requiredProp="Click me" 
    onClick={() => alert('Clicked!')}
  />
);
```

## Development Workflow Guidelines

### When Creating New Components
1. **Always start with type definitions** in `src/types/`
2. **Create component directory** with all required files
3. **Write failing tests first** (TDD approach)
4. **Implement component** following established patterns
5. **Create comprehensive stories** for all variants
6. **Run quality checks**: `npm run lint:fix && npm run test`

### When Modifying Existing Components
1. **Update type definitions first** if props change
2. **Update tests** to reflect new behavior
3. **Update stories** to showcase new functionality
4. **Maintain backward compatibility** when possible
5. **Document breaking changes** clearly

### Code Quality Checklist
- [ ] TypeScript compiles without errors or warnings
- [ ] All tests pass (`npm run test`)
- [ ] Biome linting passes (`npm run lint`)
- [ ] Component has proper accessibility attributes
- [ ] Stories cover all major use cases
- [ ] Types are properly exported and documented

## Common Patterns & Best Practices

### Props Destructuring
```tsx
// Good: Destructure with defaults and rest props
const Component: React.FunctionComponent<Props> = ({
  required,
  optional = 'default',
  className,
  ...rest
}) => {
  return <div className={className} {...rest}>{required}</div>;
};
```

### Conditional Rendering
```tsx
// Good: Clear boolean conditions
{isVisible && <Component />}
{error ? <ErrorMessage /> : <SuccessMessage />}
```

### Event Handling
```tsx
// Good: Proper event typing and optional chaining
const handleClick = (event: React.MouseEvent<HTMLButtonElement>) => {
  event.preventDefault();
  onClick?.(event);
};
```

## Performance Considerations

### Component Optimization
- **React.memo**: Use for expensive components that receive stable props
- **useCallback/useMemo**: Use judiciously for expensive calculations
- **Prop drilling**: Avoid deep prop passing, consider context when appropriate

### Bundle Size
- **Tree shaking**: Ensure components can be imported individually
- **External dependencies**: Minimize and justify all dependencies
- **Code splitting**: Support lazy loading for heavy components

## Accessibility Standards

### Required Attributes
- **Semantic HTML**: Use appropriate HTML elements
- **ARIA labels**: Provide context for screen readers
- **Keyboard navigation**: Support tab order and keyboard interactions
- **Color contrast**: Ensure sufficient contrast ratios

### Testing Accessibility
```tsx
// Include accessibility tests
expect(screen.getByRole('button')).toBeInTheDocument();
expect(screen.getByLabelText('Button label')).toHaveAttribute('aria-pressed');
```

## Error Handling Patterns

### Component Error Boundaries
- **Graceful degradation**: Components should handle missing props gracefully
- **Helpful error messages**: Use TypeScript to catch errors at compile time
- **Runtime validation**: Validate critical props when necessary

### Development vs Production
- **Development warnings**: Use console.warn for development guidance
- **Production silence**: Ensure no console output in production builds

## Troubleshooting Common Issues

### TypeScript Errors
- **Check imports**: Ensure type imports use `import type`
- **Verify exports**: Check that types are properly exported
- **Props interface**: Ensure component props match interface exactly

### Build Issues
- **Clear cache**: Delete `node_modules` and reinstall if needed
- **Check config**: Verify vite.config.ts and tsconfig files
- **Dependency conflicts**: Check for version compatibility

### Test Failures
- **Mock setup**: Ensure proper mocking for external dependencies
- **Async operations**: Use proper async/await patterns in tests
- **DOM cleanup**: Tests should clean up after themselves
